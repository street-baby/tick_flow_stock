# Terminal Dense 全站视觉重设计

## 1. 目标

在不改变现有功能入口、策略算法、数据源和交易逻辑的前提下，将 TickFlow Stock Panel 统一升级为适合长期盯盘的专业金融终端界面。

设计采用用户确认的方向：

- 视觉范式：Terminal Dense，参考 Bloomberg Terminal 的数据优先和紧凑层级。
- 动效强度：适中，只在数据变化、信号触发和连接状态变化时强调。
- 主题：深色与浅色双主题。
- 布局：保留现有导航和页面结构，重做视觉层、公共组件和信息层级。
- 产品语义：优先服务 A 股短线、14:30 尾盘扫描、资金流、守价信号、交易计划和风险控制。

## 2. 设计原则

### 2.1 数据优先

数值、信号、风险和时间状态必须始终比装饰元素更醒目。背景纹理、发光效果和水元素不能降低表格、图表或交易计划的可读性。

### 2.2 专业终端而非游戏界面

界面使用紧凑排版、细边框、明确分区和稳定的工作区结构。赛博朋克感通过冷色状态光、精细网格和有限的高亮表现，不使用大面积霓虹渐变、装饰球体、持续闪烁或夸张的卡片堆叠。

### 2.3 A 股颜色语义

上涨使用红色，下跌使用绿色。冷青色只表示连接、选中、实时和主要操作；琥珀色表示提醒；品红色仅用于异常波动或最高优先级警告，不能与涨跌方向混用。

### 2.4 稳定布局

图表、表格、工具栏和交易操作区具有稳定尺寸。hover、加载和动画不能改变布局或造成数据跳动。

## 3. 视觉系统

### 3.1 设计令牌

延续现有 HSL/CSS 变量体系，在 `index.css` 和主题工具中集中管理以下语义令牌：

- 页面底色、工作区底色、浮层底色。
- 一级、二级和弱化边框。
- 主要、次要和弱化文本。
- 实时/选中冷青色。
- A 股上涨红、下跌绿。
- 提醒琥珀色、异常品红色。
- 图表网格、扫描线、阴影和水流状态线。

深浅主题必须共享相同语义，不允许页面组件硬编码主题专用颜色。浅色主题采用冷灰白底和低饱和青色边界，避免变成普通办公后台风格。

### 3.2 表面与形状

- 页面分区主要依靠底色差异和 1px 细边框。
- 面板圆角控制在 2px 至 6px，按钮沿用小圆角。
- 不新增卡片套卡片；连续信息使用分栏、分隔线或表格承载。
- 阴影仅用于浮层、下拉菜单和需要明确层级的固定工具区。
- 数值、代码、时间和行情代码优先使用现有等宽字体栈。

### 3.3 水元素表达

水元素是状态语言，不是独立装饰：

- 资金流向使用低频水平流线或进度条表现方向。
- 数据刷新可以触发一次轻微波纹或流光。
- 当前导航、连接状态和选中区域使用细窄水线。
- 背景允许低对比网格或极弱波纹，但数据区域保持纯净。

## 4. 全站结构

### 4.1 Layout 壳层

保留现有导航和路由结构。`Layout` 统一负责：

- 桌面端导航、窄屏导航和当前页面状态。
- 顶部市场状态条。
- 主题切换和主题持久化。
- 全局数据源连接状态、最后更新时间和交易时段状态。
- 页面内容的统一宽度、间距和滚动行为。

顶部市场状态条保持紧凑，不占用主要纵向空间。连接断开、数据延迟或模拟数据必须使用文字和图标共同表达，不能只依赖颜色。

### 4.2 页面信息层级

所有页面统一采用以下顺序：

1. 页面标题、市场范围、更新时间和主要操作。
2. 关键指标数据带。
3. 主工作区，例如图表、表格、扫描结果或交易计划。
4. 辅助信息，例如解释、风控、日志和数据说明。

现有功能入口保持不变，但重复标题、重复说明和无效留白应减少。

## 5. 公共组件

### 5.1 指标单元

指标组件包含标签、主数值、变化值、时间状态和可选趋势提示。指标单元为紧凑数据块，不采用大面积装饰背景。

### 5.2 表格

全站数据表格统一：

- 固定表头和稳定行高。
- 数值右对齐、文本左对齐。
- 行情代码、价格和百分比使用表格数字样式。
- 涨跌、信号、风险和数据状态使用统一语义色。
- hover 只增强当前行定位，不改变尺寸。
- 窄屏使用可发现的横向滚动，不压缩关键列到不可读。

### 5.3 图表容器

图表容器提供统一标题栏、周期控制、图例、数据状态和更新时间。保持现有图表实现，不新增图表依赖。图表背景、网格和配色跟随主题令牌。

### 5.4 交易与风控面板

交易计划面板突出：

- 建议仓位和股数。
- 入场价、止损价和分级止盈。
- 预期持有周期。
- 当前执行状态和人工确认入口。
- 单笔风险、总仓位和当前回撤。

危险操作必须保留清晰文字，不使用只有图标的模糊表达。

### 5.5 状态组件

加载、空数据、接口错误、数据延迟、断线和模拟数据分别提供统一状态。加载使用稳定尺寸的骨架结构，错误状态提供可执行的重试操作。

## 6. 页面改造重点

- `Dashboard`：强化市场状态、关键指数、资金流、风险和当日信号的第一屏层级。
- `TradePlan`：突出入场、仓位、止损、止盈、持有周期和确认状态，减少装饰性信息。
- `Screener`：优先展示筛选条件、结果数量、信号原因和排序状态。
- `Backtest`：收益、回撤、胜率、盈亏比和样本量并列展示，风险指标不能隐藏在收益指标之后。
- `Monitor`：连接状态、刷新时间、实时异常和持仓风险保持常驻可见。
- `DarkPoolRanking`：清晰区分原始数据、推导指标、置信度和更新时间，避免将估算结果表现成确定事实。
- `Regime`：市场阶段、证据指标、策略建议和风险限制形成可扫描层级。
- 尾盘与竞价相关页面：突出 14:30 窗口、涨停守价、缩量十字星、资金方向、信号确认和失效条件。

## 7. 动效与反馈

- 行情数值变化时短暂高亮，持续约 400ms 至 700ms 后恢复。
- 资金流在数据更新时触发一次方向流动，静止时不持续抢眼。
- 高优先级尾盘信号使用边框脉冲和状态标签，不使用整屏闪烁。
- 页面进入采用轻微淡入和短距离位移。
- 图表、表格、固定工具栏和交易区不参与布局动画。
- 所有动效遵循 `prefers-reduced-motion`；关闭动效后仍显示完整状态。

## 8. 响应式与无障碍

- 桌面端保持高信息密度，窄屏按信息优先级折叠为纵向模块。
- 关键操作保持足够点击区域，中文长文本不得溢出或遮挡数据。
- 状态不能只靠颜色表达，需配合文字、图标或形状。
- 深浅主题均满足正文、关键数值和操作控件的可读对比度。
- 键盘焦点必须清晰，主题切换、导航和主要操作可通过键盘访问。

## 9. 性能约束

- 不新增 UI、动画或图表依赖。
- 动效优先使用 `transform`、`opacity` 和 CSS keyframes。
- 避免大面积实时模糊、滤镜和持续重绘。
- 高频数据变化只更新必要节点，不因视觉效果增加轮询频率。
- 页面主工作区尺寸稳定，加载和刷新不造成布局偏移。

## 10. 实施边界

本轮包含：

- 主题令牌和全局样式。
- Layout、导航、状态条和公共数据组件。
- 现有主要页面的视觉与展示结构统一。
- 适中强度动效、响应式和无障碍处理。

本轮不包含：

- 策略算法、回测逻辑和交易参数调整。
- 数据源替换或接口契约修改。
- 页面路由和功能入口重构。
- 新增交易执行能力。
- 新增第三方依赖。

## 11. 验收标准

- 深色和浅色主题均可切换并持久化。
- 所有主要页面使用统一颜色语义、边框、间距、表格和状态样式。
- A 股上涨为红色、下跌为绿色，其他状态不与涨跌语义冲突。
- 桌面和窄屏下导航、中文文本、表格、图表和交易操作区无重叠或截断。
- 数据加载、空数据、错误、断线、延迟和模拟状态可明确区分。
- 动效不会导致图表、表格或工具栏尺寸变化，并支持减少动态效果。
- 前端构建、类型检查和现有测试通过。
- 使用浏览器逐页检查 Dashboard、TradePlan、Screener、Backtest、Monitor、DarkPoolRanking 和 Regime 的深浅主题及窄屏布局。

## 12. 实施顺序

1. 建立主题令牌、基础排版和动效基础设施。
2. 改造 Layout、导航、市场状态条和主题切换。
3. 统一指标、表格、图表容器、交易面板和状态组件。
4. 按 Dashboard、TradePlan、Screener、Backtest、Monitor、DarkPoolRanking、Regime 的顺序覆盖页面。
5. 完成响应式、减少动态效果、构建测试和浏览器视觉验收。
